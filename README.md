## 项目介绍

SkillScope 是一个以个人进步为目标的电竞能力测试与练习网站。深色界面搭配荧光绿视觉元素，提供反应、精准、追踪、速度、认知、协同六个维度的专项挑战。

项目全部使用 HTML、CSS 和原生 JavaScript。无需后端、数据库、API Key、npm 安装或构建步骤，资源不依赖外部 CDN。可以直接打开 `index.html`，也可部署到 GitHub Pages 等静态托管平台。

**训练分采用公开公式，不表示电竞段位、智商或真实人群百分位。** 本项目独立开发，没有复用 arealme 的页面、素材、题库或品牌。

## 功能

- 12 项完整测试，支持自由挑战与连续综合测评。
- 入门 / 标准 / 进阶三个难度；部分基础项目保持相同条件，详见测试说明。
- 每项都有玩法说明、3 秒准备倒数和不保存成绩的练习模式。
- 正式成绩自动保存，提供个人最佳、同条件上次分数对比、六维雷达图和练习建议。
- 综合报告可以选择“最近各项成绩”或某次综合测评；未测项目明确留空。
- 单项成绩和综合报告可导出为独立绘制的 PNG，使用本地系统字体。
- 历史记录按项目、难度、输入类型筛选，提供最近 30 次训练分趋势和分页。
- JSON 导入 / 导出；校验格式、合并去重，最多保留最新 2,000 条记录。
- 姓名设置、可关闭提示音、减少界面动效、全屏测试。
- 鼠标、方向键 / WASD、空格和 Pointer Events 触摸支持。
- 切换后台、窗口失焦、Esc 或手动中止后，本轮不保存，已完成成绩保留。
- 无账号、无联网排行榜、无分析追踪；数据留在当前浏览器。

## 快速开始

### 本地直接使用

1. 下载并解压项目。
2. **保留整个目录结构**，双击根目录的 `index.html`。
3. 选择项目，先阅读说明，再练习或正式测试。

无需安装任何依赖。不要只复制 `index.html`，还需要同目录下的 `assets/`。

本地 `file://` 页面的存储、下载和全屏行为由浏览器决定。若受限，可通过下面的本地服务器或 GitHub Pages 使用。整个项目使用普通脚本，没有 ES Module 或本地 `fetch` 依赖。

### 可选：本地 HTTP 服务器

安装 Python 3 后，在仓库根目录执行：

```bash
python -m http.server 8000
```

打开 `http://localhost:8000`。这只是本地预览工具，网站不依赖 Python。

## GitHub Pages 部署（推荐：公开独立仓库）

1. 在 GitHub 新建仓库，例如 `skillscope`。准备使用免费 GitHub Pages 时，可选择公开仓库。
2. 把本项目**根目录中的全部文件和文件夹**提交到仓库根目录，确保 `index.html` 直接在仓库根目录，而不是 `skillscope/SkillScope/index.html`。
3. 保留 `.nojekyll`，让 GitHub 直接发布静态文件；网页上传界面可能遗漏隐藏文件，可使用 Git 客户端上传。
4. 打开仓库 **Settings → Pages**。
5. 在 **Build and deployment → Source** 选择 **Deploy from a branch**。
6. 在 **Branch** 选择实际使用的分支（通常是 `main`），文件夹选 **`/(root)`**，点击 **Save**。
7. 等待 Pages 构建完成，打开设置页显示的网站地址。

项目使用相对资源路径与 hash 路由，可以运行在仓库子路径下；不需要修改代码中的域名。进入测试页后的地址形如 `/#test/reaction`，刷新不会请求不存在的服务器路径。

不需要 Actions 自定义构建、不需要 `.env`、Token 或付费服务器。后续修改文件并提交到发布分支即可更新。

官方文档：

- [配置 GitHub Pages 发布源](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)
- [创建 GitHub Pages 站点](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site)

## 使用指南

### 自由挑战与综合测评

自由挑战可任意选择项目与难度。练习模式运行完整一轮，但不写入历史记录；正式模式自动保存。

综合测评按顺序进行，每项单独保存。从首项正式开始后统一锁定难度。离开后已完成项目仍保存在历史中，但本次排队流程不自动续接；可以重新开始，或单独补测并查看最近成绩报告。

触屏环境下，综合流程自动跳过实体键盘项目，包含 11 项。单独进入键盘项目后，可点击“我已连接实体键盘”启用它。输入类型由实际鼠标 / 触屏 / 键盘事件记录，连接键盘后完成的键盘成绩归入鼠标 / 键盘组，因此纯触屏报告不会生成完整 12 项总分。

### 报告与评分

- 报告按**难度 + 输入类型 + 测评范围**筛选。
- 选择“最近各项成绩”时，每项使用该范围内最近的一条成绩，而非历史最佳。
- 未测维度显示 `—`，雷达图不将其补成零分。
- 维度分取该维度已测项目的算术平均；显示覆盖数。
- 同一筛选范围下 12 项均有成绩时，才显示 12 项分数的算术平均总分。
- 站内评分公式、难度参数、指标口径见 [测试与评分说明](docs/TESTS.md)。

### 备份与迁移

1. 在“历史记录”点击“导出 JSON”。
2. 换设备或换浏览器后，点击“导入备份”并选择 JSON。
3. 检查数量提示后确认导入。

备份只包含正式记录，不包含偏好设置。相同 ID 不重复导入；超过 2,000 条时保留时间最新的记录。单个导入文件最大 5 MB。不支持任意其他网站的成绩格式。

**清理站点数据、无痕窗口关闭或更换域名可能使本地记录不可用。请定期备份。** 存储失败时仍可在本次页面会话中导出成绩。纯静态网站无法在浏览器关闭后自动备份到磁盘或跨设备同步。

### PNG 成绩图

- 在单项结果或历史记录中导出单项图。
- 在能力报告中导出报告图。
- 练习结果图会明确标注“练习成绩”。

图片由 Canvas 本地绘制，不发送成绩到服务器。完整 CPS 逐秒数据保留在网页结果与 JSON，单项图展示主要指标。

## 开发与验证

只需编辑静态文件，刷新浏览器查看。修改 `core.js` 的项目定义、评分和维度映射时，应同时更新文档。修改 `games.js` 可调整玩法，但要保持指标口径一致。

可选安装 Node.js 18 或更高版本，运行：

```bash
node --check assets/core.js
node --check assets/games.js
node --check assets/app.js
node tests/run.cjs
```

测试覆盖三种难度下的完整流程、无输入超时、计分范围、备份校验、记录去重与上限、按键连发过滤、主指针过滤、中断与监听器清理。测试不需要 npm 安装；自动状态机测试不能替代真实设备的延迟测量。

## 兼容性与测量限制

面向现代 Chrome、Edge、Firefox、Safari 及对应移动浏览器，使用 Canvas 2D、Pointer Events、`<dialog>`、Web Audio、localStorage 与 Blob 下载等标准能力。没有 IE 兼容层。完整验证范围见 [QA 文档](docs/QA.md)，未对每种真实设备和浏览器逐一实测。

计时基于 `performance.now()`，画面由 `requestAnimationFrame` 绘制。无法扣除显示、浏览器、触屏、无线音频或输入设备延迟；也无法可靠识别连点器或修改本地记录的行为，因此没有公榜与竞技认证。

测试画布使用 960 × 520 逻辑坐标，按设备像素比绘制；移动端界面适配触屏操作。尺寸与输入方式改变会影响操作难度，**请不要跨设备直接比较分数**。减少动效只影响装饰与过渡，动态追踪等必需运动仍保留。

## 常见问题

**部署后只看见 README，或出现 404？**

确认发布源文件夹中直接存在 `index.html`，Pages 分支与文件夹选择正确，并查看 GitHub 的 Pages 构建结果。不要只上传压缩包。

**页面没有样式或按钮无反应？**

确认 `assets/` 一起上传、文件名大小写未改变，资源路径未被改成 `/assets/...`。清除缓存后重试。

**没有声音？**

提示音默认关闭，在设置中启用。部分浏览器需要先点击页面才允许播放音频。全屏、后台切换或设备音量设置也可能影响体验。

**为什么切到其他窗口后测试停止？**

为了避免后台计时和渲染节流影响成绩，本轮会中止，已完成轮次保留。

**为什么没有百分位或全国排名？**

项目没有可信人群样本或服务器。显示的是公开公式的个人训练分与历史进步。

**为什么综合报告未显示总分？**

当前难度、输入类型及测评范围没有覆盖全部 12 项。触屏环境缺少实体键盘专项时也不会计算完整总分。

**为什么本地打开有记录，部署后没有？**

localStorage 按站点来源隔离；先在原页面导出 JSON，再到新页面导入。
